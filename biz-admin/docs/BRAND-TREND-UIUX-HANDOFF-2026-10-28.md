## 1. 무엇을 위한 화면인가

**MD가 기존 입점 브랜드에 신상품 공급과 텐텐 행사 참여를 제안할 근거를 찾는 화면**이다. 판매처별 상품을 나열하는 것보다 다음 질문에 답하는 것이 우선이다.

1. 이 브랜드는 지금 외부 어느 판매처에서 어떤 행사를 하고 있는가?
2. 같은 기간 텐텐 행사에도 참여했는가? 아직 확인하지 못한 것인가?
3. 외부에서 발견한 상품이 텐텐에도 등록돼 있는가?
4. 같은 상품·구성이라면 텐텐과 외부 판매가, 공개 쿠폰 조건은 어떻게 다른가?
5. MD가 다음에 할 일은 브랜드 상담인가, 동일 상품 확인인가, 수집 담당자 문의인가?

주 사용자는 위임운영 B급 업체를 관리하는 MD다. 처음 사용하는 MD도 **현재 브랜드 → 확인된 사실 → 비교 결과 → 다음 행동**을 읽을 수 있어야 한다.

요청받은 원형은 행사 피드·브랜드별 12주 타임라인·관심 브랜드·수집 상태의 네 화면이다. 이후 상품 등록 대조·가격 비교와 브랜드 검색을 추가했다. 상품 현황은 행사 참여 판단을 보조하며, 상품 할인만으로 기획전 참여를 판정하지 않는다.

참고 와이어프레임: [Claude 브랜드 트렌드 v0.3](https://claude.ai/artifact/Dr73RVanmYhDVfRSgThRDk#play-a19ad96a5ca0). 기존 요청의 참고 자료이며, 현재 구현과 완전히 동일한 상태를 의미하지 않는다.

## 3. 화면별 현재 작업 내용

### 행사 피드

- 첫 화면이다. 상단 숫자 3개는 현재 필터의 외부 행사 기준으로 오늘 발견·진행 중·진행 중이면서 같은 기간 텐텐 참여 미확인 건수를 보여준다.
- 브랜드·기간·판매처·같은 기간 텐텐 참여 상태로 좁힐 수 있다.
- 브랜드 단위 접기와 개별 행사 상세 펼침을 유지했다. 행사 배지·원문·기간·참여 근거를 제공한다.
- 상세에는 참여 상품 카드, 외부 표시가·공개 쿠폰, 텐텐 등록·판매 정보와 같은 기간 텐텐 행사가 있다.
- 최근 변경: 하단 요약을 **브랜드별 행사 수집 현황**으로 바꾸고 현재 브랜드 이름을 표시했다. ‘행사 확인 필요’는 문제가 기록된 **브랜드×판매처 조합 수**다.
- 외부 행사 0건이면 수집 범위·실패 상태를 확인하도록 안내한다. 텐텐 이력이나 외부 상품 수로 외부 행사 수를 대신 채우지 않는다.

### 행사 일정

- 최근 12주에 브랜드가 언제·어느 판매처 행사에 참여했는지 확인하는 화면이다.
- 최근 변경: 합계 숫자의 반복을 줄이고 **브랜드별 외부 행사 / 텐텐 행사 기록**을 먼저 배치했다. 어느 브랜드의 기록인지 행마다 명시한다.
- 브랜드 이름을 누르면 해당 브랜드로 좁혀진다. 전체 보기로 되돌릴 수 있고 원래 텐텐 ID는 펼쳐서 확인한다.
- 12주 달력은 기본으로 펼쳐진다. 판매처·주간 칸을 누르면 아래 행사 목록을 좁히며 같은 칸을 다시 누르면 해제한다.
- 외부 자료가 부족하면 판매처 연결 확인 → 수집 실행·로그 또는 최근 수집 결과 확인으로 이어진다.
- 여러 주에 걸친 같은 행사는 주마다 보이지만 전체 건수는 한 건이다. 주간 칸 숫자를 모두 더하는 방식으로 총계를 만들면 안 된다.

### 상품 현황

- 현재 제목은 **수집한 외부 상품**이다. 실제로 수집된 브랜드와 자료가 없는 브랜드를 나눠 안내한다.
- 최근 변경: 상품 사진·브랜드·상품명·발견 판매처 배지와 원문을 먼저 보여주고, 옆에서 텐텐 등록·가격과 외부 판매가·쿠폰을 비교하도록 정리했다.
- 여러 판매처에서 동일 상품을 확인하면 한 상품에 판매처별 조건을 함께 보여준다. 단순 유사 후보는 동일 상품 확정과 구분한다.
- 브랜드와 상품·모델명 검색은 바로 노출한다. 판매처·등록·가격·정렬·쿠폰은 **상세 필터** 안에 모았다.
- 상품 목록 / 전체 가격 그래프를 전환할 수 있다. 개별 상품의 날짜별 가격 변동도 유지했다.
- 사진이 없거나 로드되지 않으면 사진 미확인 자리를 남긴다. 유사 후보의 다른 상품 사진으로 채우지 않는다.
- 자료 없는 브랜드를 선택해도 다른 브랜드의 상품을 대신 보여주지 않는다. 해당 브랜드의 연결 확인으로 안내한다.

### 브랜드 검색·관심 관리

- 텐텐 브랜드 이름 또는 ID로 검색 → 판매처 후보 확인 → 선택 내용을 등록 초안에 추가 → 최종 저장 순서다.
- 같은 원장 이름의 여러 ID는 묶되 ID를 보존한다. 로이체는 `khretail_9`, `royche`, `royche10`, `royche45`의 4개 ID를 합쳐 관리한다.
- 후보를 초안에 담은 상태와 저장 완료를 구분한다. 저장된 링크는 후보 검색이 제한돼도 바로 열 수 있다.
- 검색은 관심 등록 전에도 가능하다. 관심 대상의 등록·수정은 관심 관리에서 한다.
- 새 판매처 후보는 화면 안에서 확인한다. 후보 발견만으로 공식 판매처 확정·자동 연결·자동 수집하지 않는다.
- 아르디움은 확인된 공식몰·오늘의집 후보를 검색 제한 시에도 제공한다. 다른 판매처의 후보 미확인은 미입점을 뜻하지 않는다.

### 수집 상태

- 판매처마다 **상품·가격 관측 결과**와 **행사 목록 확인 결과**를 구분한다.
- 마지막 시도·전체 수집 마지막 성공·건수·실패 원인과 조치를 표시한다.
- 일부 실패해도 확인된 상품과 이전 기록을 유지한다. 상품 20개 수집 성공과 행사 목록 해석 실패가 동시에 있을 수 있다.
- 자료 새로고침은 저장 자료를 다시 읽는다. 실제 수집 실행은 에이전트 센터에서 한다.

## 4. UI/UX를 이어서 개선할 방향

다음은 완료된 디자인이라고 보기보다, 사용자 피드백을 기준으로 다시 설계할 우선순위다.

1. **범위부터 분명하게:** 전체 관심 브랜드인지 선택한 브랜드인지, 현재 보이는 상품이 어느 브랜드 것인지 한 곳에서 명확하게 보여준다. 같은 범위 설명을 여러 번 반복하지 않는다.
2. **업무 판단을 먼저:** 행사명·기간·판매처·텐텐 참여 여부, 상품명·텐텐 등록 여부·판매처별 가격이 기술 정보보다 먼저 보여야 한다.
3. **0건의 다음 행동:** 행사 없음, 목록 일부 확인, 수집 실패, 미수집을 구분하고 각 상태에서 한 가지 우선 행동을 제시한다.
4. **의미 있는 시각 차이:** 기존 biz-admin 트렌드 HUB의 틀과 텐텐 스타일을 유지하면서 행사·판매처·판단 상태에 일관된 배지와 위계를 적용한다. 색상만으로 의미를 전달하지 않는다.
5. **첫 상품을 빨리 확인:** 상품 목록 위의 설명·숫자·필터가 차지하는 높이를 줄이고 사진·상품명·가격 비교가 먼저 눈에 들어오게 한다.
6. **PC와 모바일 모두:** PC는 본문 폭을 충분히 쓰고 비교 정보를 함께 보여준다. 모바일은 상품 정체성 → 비교 조건 → 상세 근거 순서로 쌓는다. 긴 이름·여러 배지·사진 누락에도 정렬이 유지돼야 한다.

배치·표/카드 형태·문구·강조 방식은 변경할 수 있다. 아래 동작과 데이터 의미는 유지해야 한다.

## 5. 디자인을 바꿔도 유지할 동작·판정

| 항목 | 유지 기준 |
|---|---|
| 브랜드 선택 | 첫 브랜드를 임의로 선택하지 않는다. 피드·일정·상품의 브랜드 필터는 각각 독립적이다. |
| 동일 브랜드 여러 ID | 합산 범위를 표시하고 원래 ID를 확인할 수 있게 한다. 이름이 다른 브랜드를 임의로 합치지 않는다. |
| 행사 건수 | 브랜드×판매처×기획전 단위. 여러 날 수집해도 같은 행사를 중복 집계하지 않는다. |
| 행사 기간 | 판매처 표기 기간을 우선하고, 관측일만 있는 경우 별도로 구분한다. |
| 텐텐 참여 | 선택 범위 브랜드의 행사 이력이다. 텐텐 전체 행사나 동일 상품의 참여를 뜻하지 않는다. |
| 미확인 | 미참여·미입점·미등록·0원으로 바꾸지 않는다. 실패와 확인 기록 없음을 구분한다. |
| 상품 자동 대조 | 구체적인 상품명·모델과 유일 후보 등 근거가 충분하면 자동 확인한다. 애매한 후보만 MD 확인으로 남긴다. |
| 상품 등록과 가격 | 등록 확인과 동일 옵션·구성 확인은 별개다. 조건이 부족하면 가격 차이를 확정하지 않는다. |
| 판매가·쿠폰 | 표시 판매가와 공개 쿠폰 조건을 분리한다. 추정 최저가를 만들지 않는다. |
| 가격 그래프 | 실제 저장 관측과 시각을 사용한다. 수집 공백을 임의로 잇거나 현재 텐텐 가격을 과거로 소급하지 않는다. |
| 외부 링크 | 실제 발견 판매처와 원문을 유지한다. 링크 보관과 자동 수집 지원을 구분한다. |
| 펼침·필터 | 브랜드 접기, 행사 상세, 기본 열린 달력, 검색·필터·초기화와 가격 그래프 접근을 유지한다. |

## 8. 실행·검증 방법

기술 구성: Next.js 16 / React 19 / TypeScript / Tailwind CSS 4 / 공통 UI 컴포넌트. 로컬 요구사항은 Node.js 22 이상이다. 설정은 저장소 `README.md`를 참고하고 비밀값·쿠키를 문서나 테스트 데이터에 넣지 않는다.

```bash
# 저장소 루트에서 실행. 의존성 설치는 최초 1회
npm install
npm run dev -- --port 3193

# 변경 후 확인
npm test -- tests/unit/brand-trend
npx tsc --noEmit --incremental false
# 수정한 화면 파일을 지정해 린트
npm run lint -- src/app/brand-trend/page.tsx src/components/brand-trend
```

개발 주소: `http://localhost:3193/brand-trend`. 포트가 사용 중이면 다른 포트를 지정한다. 실제 원장 조회·저장은 기존 인증과 환경 설정이 필요하다. UI 확인용 스냅샷·예시 자료는 실제 운영 수집 결과와 구분한다.

최신 UI 코드의 검증 이력: 브랜드 트렌드 단위 시험 **44개 파일·299개 시험**, 타입 검사, 변경 파일 린트 통과. 운영 읽기 전용 자료를 이용한 로컬 PC·모바일 확인에서 가로 넘침, 브랜드 선택·해제, 자료 없는 브랜드, 가격 그래프·상품 검색·판매처 필터를 확인했다. 이는 최신 코드의 운영 배포 완료나 새 외부 행사 수집 성공을 의미하지 않는다. 이 문서 작성 시 시험을 다시 실행하지는 않았다.

UI 수정 후에는 특히 다음 상태를 함께 확인한다.

- 전체 관심 브랜드 / 명시적으로 선택한 브랜드 / 자료 없는 브랜드.
- 행사 있음 / 외부 행사 0건 / 일부 수집 실패 / 전체 수집 실패.
- 상품 사진 있음·없음·로드 실패, 긴 이름, 여러 판매처와 공개 쿠폰.
- 텐텐 등록 확인 / 애매한 후보 / 검색에서 못 찾음 / 조회 실패.
- 가격 미확인·품절·이전 관측과 동일 구성 비교 가능 상태.
- PC·모바일, 키보드 조작·포커스, 접기·펼치기 후 필터와 범위 유지.

## 9. 수집·배포 작업과의 경계

Python + Playwright 워커는 `workers/brand-trend/`에 있다. 워커가 수집 마트를 만들고 앱은 읽는다. 관심 등록부는 별도 JSON으로 앱이 관리하며 텐텐 운영 DB에 쓰지 않는다.

UI 작업 때문에 운영 수집을 반복 실행하거나 예약·RunLog·Slack을 임의로 변경할 필요는 없다. 실제 수집 실행과 알림 도착·저장은 별도로 검증한다. 매일 06:00 KST 예약은 활성화 상태를 확인해야 하며 UI가 있다고 실행 중이라고 가정하지 않는다.

배포는 서버에서 `pull → plan → up → status` 순서다. `plan`이 변경된 앱·워커를 판정하며 앱 화면만 수정했다면 워커 입력 변경이 없는지 확인한다. `status`만 실행하면 배포되지 않는다. 마지막 사용자 배포 기록의 앱 빌드는 518초, 전체 약 9분 28초였고 즉시 배포로 개선된 상태는 아니다. 현재 속도는 다음 배포에서 다시 측정해야 한다.
